The problem

A link that looks right is the easiest way in

Imagine receiving https://amaz0n-security-login.example. It reads like an Amazon page, but it can be a fake built to steal a password. Normally the link would simply be clicked. SecureBrowse turns that silent moment into a checked decision.

What the address is actually doing

https://amaz0n-security-login.example
  • amaz0n — a zero replaces the “o” to imitate a brand.
  • -security-login — credential wording borrowed from real login pages.
  • .example — not the brand’s real domain, so the trust is unearned.

Each of those traits alone is weak evidence. Together they form a pattern.

What SecureBrowse answers

  1. 1 Is this address built like a legitimate one?
  2. 2 Has a threat source already reported it?
  3. 3 How strong is the combined evidence?
  4. 4 Which class does the score fall into?

Every verdict carries its reasons, and every incomplete check is named.

      Adding the two account keys

      Each key is free but tied to your own account, so it cannot be generated for you. Copy .env.example to .env, paste the value after the variable name, then restart python app.py and press Sync feeds.

      • URLHAUS_AUTH_KEY — auth.abuse.ch (GitHub or Google sign-in)
      • GOOGLE_SAFE_BROWSING_KEY — Google Cloud → Safe Browsing API
      • PHISHTANK_APP_KEY — optional; raises the PhishTank download limit

      Before enabling an integration, check the provider’s current API or feed documentation, access requirements, rate limits and usage terms. An API failure is never read as “safe”.
